# PostgreSQL Migration Audit

The backend has a `postgres` Spring profile and PostgreSQL/Flyway dependencies,
but production PostgreSQL startup intentionally remains fail-closed until the
Flyway migration set is made vendor-ready.

## Current Status

- H2 remains the supported local database.
- PostgreSQL datasource configuration is reserved in `application-postgres.yml`.
- `DatabaseMigrationGuard` blocks non-H2 datasources unless
  `DATABASE_ALLOW_NON_H2=true` is explicitly set.
- The override is for controlled migration experiments only, not production.

## Known Non-Portable SQL

The current migration set includes H2-specific or H2-tolerant SQL patterns that
need a vendor-specific pass before PostgreSQL can be enabled safely:

- `AUTO_INCREMENT`
- `RANDOM_UUID()`
- `IF NOT EXISTS` on some `ALTER TABLE`, `ADD COLUMN`, `ADD CONSTRAINT`, and
  index statements
- `DROP COLUMN IF EXISTS`
- H2-style `ALTER COLUMN`
- Mixed identity syntax across migrations

Some types such as `UUID`, `BOOLEAN`, and `TIMESTAMP` are generally compatible
with PostgreSQL, but each table still needs to be reviewed together with its
defaults, constraints, indexes, and seed data.

## Recommended Migration Strategy

1. Keep existing H2 migrations as the local/demo migration stream.
2. Add a PostgreSQL-specific Flyway location, for example
   `db/migration/postgresql`.
3. Create a clean PostgreSQL baseline migration that represents the current
   schema after all existing H2 migrations.
4. Replace H2 functions:
   - `RANDOM_UUID()` -> `gen_random_uuid()` with `pgcrypto`, or generate UUIDs
     in Java seed code.
   - `AUTO_INCREMENT` -> `GENERATED BY DEFAULT AS IDENTITY`.
5. Rewrite idempotent DDL where PostgreSQL does not support the H2 form.
6. Run a PostgreSQL Testcontainers migration test before enabling non-H2
   datasources by default.
7. Only then allow production startup with the `postgres` profile.

## Acceptance Criteria

- PostgreSQL migrations run from an empty database.
- Hibernate `ddl-auto=validate` passes against PostgreSQL.
- Existing backend tests pass against H2.
- A PostgreSQL migration smoke test passes in CI.
- The fail-closed guard remains enabled for unsupported database vendors.
